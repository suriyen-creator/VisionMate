### 3.1 PND-01: การขาดชุดข้อมูล Ground Truth Annotation (mAP@0.5)

- **ความเสี่ยงหากกล่าวอ้าง:** หากนักศึกษาระบุว่า "ระบบมีความแม่นยำในการตรวจจับ 92%" โดยไม่มีชุดข้อมูลทดสอบและสคริปต์คำนวณ จะถือเป็นการสร้างข้อมูลเท็จทางวิชาการ (Data Fabrication)
- **แนวทางแก้ไขสำหรับบทที่ 4:**
  1. บันทึกภาพจากกล้อง USB ที่ติดตั้งในอุปกรณ์จำนวน 50–100 ภาพ ครอบคลุมสภาพแสง 3 สภาพ (สว่าง, ปกติ, มืด)
  2. วาดกรอบสี่เหลี่ยมด้วยโปรแกรม **LabelImg** หรือ **Roboflow** บันทึกเป็น YOLO Annotations
  3. เขียนสคริปต์ Python คำนวณ Intersection over Union (IoU) ที่เกณฑ์ 0.50 เพื่อหา True Positive (TP), False Positive (FP), และ False Negative (FN)
  4. คำนวณค่า Precision, Recall และ mAP@0.5 ตามมาตรฐานวิชาการ

### 3.2 PND-02: การสอบเทียบระยะทางกายภาพจริง (Physical Distance Calibration)
- **สภาพปัจจุบัน:** ฟังก์ชัน `classify_distance()` ใน [`app.py`](file:///home/fablab-rp-21/edge_ai_project/app.py#L427-L450) ใช้สูตรประเมินจากตำแหน่งขอบล่างของภาพ ($y_{\text{bottom}}$) และสัดส่วนพื้นที่ (Bounding Box Area Ratio):
  - วัตถุขนาดเล็ก (เช่น แก้วน้ำ, มือถือ): ขอบล่าง $\ge 0.55$ หรือ Area $\ge 0.035 \rightarrow$ ระยะใกล้
  - วัตถุขนาดใหญ่ (เช่น เก้าอี้, คน): ขอบล่าง $\ge 0.72$ หรือ Area $\ge 0.18 \rightarrow$ ระยะใกล้
- **ความคลาดเคลื่อนที่พบ (จากผลทดสอบ Suite F):**
  - ในความละเอียด 640 × 480 พิกัด $y$ เป็นจำนวนเต็มพิกเซล ส่งผลให้จุดตัดทางคณิตศาสตร์ $0.72$ มีค่าจริงบนพิกเซลคือ $345/480 = 0.71875$ ทำให้เกิด Quantization Discretization Error $\pm 0.002$
  - หากวัตถุถูกวางบนโต๊ะสูง ขอบล่างของวัตถุจะอยู่สูงในภาพ ($y$ ต่ำ) ทำให้ระบบประเมินว่าเป็น "ระยะไกล" ทั้งที่วัตถุอยู่ใกล้ผู้ใช้จริง
- **แนวทางแก้ไขสำหรับบทที่ 4/5:**
  - นำตลับเมตรหรือเลเซอร์วัดระยะทาง (Laser Rangefinder) วัดระยะจริงจากหน้าเลนส์กล้องที่ระยะ 30, 50, 70, 100, 150 และ 200 เซนติเมตร
  - วางวัตถุมาตรฐาน เช่น ขวดน้ำ หรือ แก้วน้ำ แล้วบันทึกพิกัดและขนาด Bounding Box เพื่อสร้างโมเดลการแปลงพิกเซลเป็นระยะทางจริง (Monocular Depth Calibration Regression Model)

### 3.3 PND-03: การทดสอบความเค้นต่อเนื่อง 10 นาที (Stress Test Under Load)
- **สภาพปัจจุบัน:** ในการทดสอบ Benchmark ได้ทำการเก็บข้อมูลเป็นรอบ ๆ โดยเว้นระยะพัก (Sequential Execution with Cooldown) เพื่อป้องกันความร้อนสะสมเกินขีดจำกัด
- **ข้อสังเกตจาก Audit:** อุณหภูมิสูงสุดที่เคยวัดได้คือ **53.0°C** ภายใต้โหลดระยะสั้น (30 เฟรมติดต่อกัน) และไม่มีสถานะ Throttled (`0x0`) แต่ยังไม่มีหลักฐานการทำงานต่อเนื่องระดับ 10–30 นาทีขณะเปิดกล้องและรัน LLM ถี่ ๆ
- **แนวทางแก้ไข:**
  - หากต้องการนำระบบไปติดตั้งในกระเป๋าเป้หรือเคสพกพาของผู้พิการทางสายตา ต้องทดสอบรันแอปพลิเคชันต่อเนื่องอย่างน้อย 30 นาทีในกล่องปิดทึบ และบันทึกอุณหภูมิ CPU ทุก 10 วินาที เพื่อดูว่าอุณหภูมิเกิน 80.0°C จนเกิดการลดความเร็วสัญญาณนาฬิกา (CPU Thermal Throttling) หรือไม่

### 3.4 PND-04: การยืนยันประสิทธิภาพบน Raspberry Pi 4 รุ่น RAM 4 GB
- **สภาพปัจจุบัน:** เครื่องที่ใช้ทดสอบจริงคือ **Raspberry Pi 4 Model B Rev 1.5 มี RAM 8.0 GB (ตรวจพบ 7,819.8 MB)**
- **ข้อสรุปเชิงวิศวกรรม:**
  - ในการรันระบบทั้งหมดพร้อมกัน (OS + YOLOv8n + Qwen2.5-0.5B + Pygame) ระบบใช้ RAM รวมสูงสุด **2,056 MB** และเหลือ RAM ว่าง (Available RAM) มากกว่า **5.6 GB** ตลอดการทดลอง
  - ในทางทฤษฎี ระบบน่าจะทำงานได้บนบอร์ดรุ่น RAM 4 GB (เนื่องจาก 2,056 MB < 4,000 MB) แต่เนื่องจากบอร์ดรุ่น 4 GB มี Memory Bandwidth และการจัดสรรหน่วยความจำร่วมกับ GPU VRAM แตกต่างกัน จึง **ยังไม่อนุญาตให้อ้างว่าได้ทดสอบบนบอร์ด 4 GB แล้ว**
- **แนวทางแก้ไข:**
  - ยืมบอร์ด Raspberry Pi 4 RAM 4 GB มารันทดสอบสคริปต์ `benchmark_latency.py` และ `benchmark_resources.py` ซ้ำ เพื่อยืนยันว่าไม่มีการสลับหน้าหน่วยความจำลงดิสก์ (Swap Thrashing)

### 3.5 PND-05: การวัดความหน่วงของสัญญาณเสียงออกสู่หูฟัง (Acoustic DAC Latency)
- **สภาพปัจจุบัน:** ในชุดทดสอบ Suite E ได้ทำการวัดเวลาละเอียดตั้งแต่กล้องรับภาพจนถึงจุดที่คำสั่งโหลดบัฟเฟอร์เสียงสำเร็จใน Pygame:
  - `Camera-to-Detection`: 274.48 ms
  - `Camera-to-Audio-Command`: 278.40 ms
  - `Audio File Read Latency` (/dev/shm): 0.17 ms
  - `Audio Buffer Load Latency`: 0.54 ms
- **ข้อจำกัดทางเครื่องมือ:** ตัวเลข 278.40 ms นี้ยังไม่รวมเวลาที่ระบบปฏิบัติการ Linux ALSA ส่งข้อมูลผ่านตัวแปลงสัญญาณดิจิทัลเป็นแอนะล็อก (DAC), เวลาขยายสัญญาณของแอมพลิฟายเออร์ และเวลาที่คลื่นเสียงเดินทางผ่านอากาศเข้าสู่หูผู้ฟัง
- **แนวทางแก้ไข:** สำหรับงานวิจัยระดับสูงขึ้นไป สามารถใช้สายสัญญาณเสียงต่อเข้า Digital Storage Oscilloscope (DSO) หรือใช้ไมโครโฟนความเร็วสูงดักฟังเสียงจากหูฟังเทียบกับสัญญาณไฟ LED จากกล้อง เพื่อหา Acoustic Latency ที่แท้จริง

### 3.6 PND-06: ความปลอดภัยในการนำทางในสภาพแวดล้อมเปิด (Safety Certification)
> [!CAUTION]
> **ข้อห้ามสำคัญทางวิชาการและจริยธรรม:**  
> **ห้ามระบุในบทที่ 5 หรือในบทคัดย่อว่า "ระบบสามารถช่วยให้ผู้พิการทางสายตาสัญจรได้อย่างปลอดภัย"**

- **เหตุผลทางวิศวกรรม:**
  1. กล้องเดี่ยว (Monocular Camera) มีจุดบอดด้านระยะชัดลึก (Depth Blindness) ไม่สามารถตรวจจับพื้นต่างระดับ หลุม บันไดทางลง หรือสิ่งกีดขวางโปร่งใส (เช่น ประตูกระจก) ได้
  2. อัตราการประมวลผลของระบบตรวจจับภาพอยู่ที่ประมาณ 3.6–5.3 FPS หากมีวัตถุเคลื่อนที่เร็ว (เช่น จักรยานยนต์ วิ่งด้วยความเร็ว 30 กม./ชม. หรือ 8.3 เมตร/วินาที) ในช่วงเวลาประมวลผล 1 เฟรม วัตถุจะเคลื่อนที่เข้าใกล้ผู้ใช้ไปแล้วเกือบ 2 เมตร ซึ่งอันตรายถึงชีวิต
  3. ระบบขาดอุปกรณ์ตรวจจับสิ่งกีดขวางระยะประชิดแบบ Fail-Safe เช่น เซนเซอร์คลื่นเสียงอัลตราโซนิก (Ultrasonic) หรือเลเซอร์วัดระยะ (Time-of-Flight: ToF)
- **ข้อเสนอแนะในการสรุปโครงงาน:** ให้สรุปว่าเป็น **"ระบบต้นแบบผู้ช่วยระบุตำแหน่งและบรรยายวัตถุรอบตัวในสภาพแวดล้อมปิดหรือกึ่งควบคุม (Controlled Laboratory / Indoor Environment)"** เพื่อช่วยเสริมการรับรู้สภาพแวดล้อมร่วมกับไม้เท้าขาวเท่านั้น ไม่สามารถใช้ทดแทนไม้เท้าขาวหรือการตัดสินใจของผู้ใช้ได้
