# สรุปผลการทดลองเชิงตัวเลขและข้อค้นพบทางเทคนิค (Experimental Summary)
**โครงงาน:** ระบบผู้ช่วยบรรยายสภาพแวดล้อมและค้นหาสิ่งของสำหรับผู้พิการทางสายตาด้วยเทคโนโลยี Edge AI และ Local LLM บน Raspberry Pi 4  
**บันทึกเมื่อ:** 29 ตุลาคม 2026  
**สถานะการทดสอบ:** ดำเนินการทดสอบเสร็จสมบูรณ์บนอุปกรณ์ Raspberry Pi 4 เครื่องจริง

### 1.4 สรุปผลความทนทานต่อข้อผิดพลาด (Robustness & Edge Cases)
วิเคราะห์จาก `robustness_tests.csv`:
- **อัตราการผ่านการทดสอบ:** 7 ผ่านสมบูรณ์ (PASS), 1 ผ่านบางส่วน (PARTIAL: เกิดจากระบบแคชเสียงเพิ่งสร้างไฟล์แรกก่อนเปิดลูปเต็ม)
- **การป้องกันกล้องมืด (ROB_01):** Mean Brightness < 25.0 ตรวจจับได้ทันทีและเปลี่ยนไปเล่นเสียงเตือน `camera_dark`
- **การป้องกันกล้องเบลอ/นิ้วบัง (ROB_02):** Variance of Laplacian < 15.0 ตรวจจับได้ถูกต้อง
- **การจัดการกรณีไม่พบวัตถุ (ROB_04):** ระบบคืนค่าประโยคแจ้งเตือนสุภาพ ไม่เกิด Exception
- **LLM Timeout Fallback (ROB_05):** เมื่อการเรียก Ollama ล่าช้าเกินกำหนด ระบบสลับมาใช้ Python Narrative ภายในเวลา <0.01 ms โดยอัตโนมัติ
- **gTTS Network Error Handling (ROB_06):** ระบบดักจับ `ConnectionError` ได้ปลอดภัย ไม่ทำให้เธรดหลักหยุดชะงัก
- **Pause Responsiveness (ROB_08):** การกดปุ่ม Space/P สามารถหยุดการรอได้ทันทีใน 0.102 วินาที (จากเวลาหน่วงเดิม 2.0 วินาที)

## 2. ข้อค้นพบทางเทคนิคเชิงลึก (Critical Engineering Insights)

1. **การตรวจสอบฮาร์ดแวร์จริง:**  
   อุปกรณ์จริงเป็น **Raspberry Pi 4 Model B Rev 1.5 ขนาด RAM 8 GB (7.6 GiB)** ไม่ใช่ 4 GB ตามสมมติฐานเบื้องต้น ทำให้หน่วยความจำไม่เคยเข้าใกล้จุดวิกฤต (Swap ถูกใช้งาน 0 MB ตลอดเวลา)
2. **สาเหตุทางเทคนิคของ LLM Timeout (Prompt Token Saturation):**  
   จากการวิเคราะห์ลึกใน Ollama Journal Log พบว่า Prompt ภาษาไทยพร้อมตัวอย่าง Few-shot มีความยาวถึง **252 โทเคน** ในขณะที่ค่า `num_ctx` ใน `app.py` ถูกตั้งไว้ที่ **256** ส่งผลให้พื้นที่ Context Window เต็มถึง 98.4% ตั้งแต่ขั้นตอน Prompt Ingestion ทำให้ Ollama ต้องสลับพื้นที่ Context Slot ทันทีที่เริ่มสร้างประโยค ส่งผลให้เวลาตอบสนองเพิ่มขึ้นเป็น 8.5–11.7 วินาที ซึ่งเกินกว่า Timeout 8.0 วินาทีที่ตั้งไว้ในแอป ส่งผลให้ระบบสลับมาใช้ Python Fallback เกือบทุกครั้ง
3. **ความถูกต้องของแนวคิด Hybrid Architecture:**  
   การออกแบบให้มี **Fast Path (Python Rule-based)** คู่กับ **LLM Path** ถือเป็นการตัดสินใจเชิงวิศวกรรมที่ถูกต้องและจำเป็นอย่างยิ่ง เพราะบนหน่วยประมวลผล CPU Cortex-A72 ของ Raspberry Pi 4 การประมวลผล Fast Path ทำงานได้ที่ความเร็ว ~3.6 FPS (Latency รวม ~276 ms) ซึ่งเพียงพอต่อความปลอดภัยในการแจ้งเตือนสิ่งกีดขวางระยะประชิด ต่างจาก LLM Path ที่ต้องใช้เวลานานเกือบ 10 วินาที
4. **ข้อจำกัดของโมเดลขนาดเล็ก (0.5B) ในภาษาไทย:**  
   โมเดล Qwen2.5-0.5B มีแนวโน้มยึดติดกับตัวอย่างใน Prompt (Few-shot anchoring) เมื่ออินพุตมีความขัดแย้งกับตัวอย่าง เช่น ในกรณีห้องมืด โมเดลกลับเลือกที่จะลอกประโยค "แสงสว่างปกติครับ มีแก้วน้ำสีแดง" จากตัวอย่างในคำสั่งมาตอบ

## 3. ข้อมูลที่ยังขาดและรายการที่ต้องเก็บเพิ่มสำหรับจัดทำรายงานบทที่ 4–5

1. **Object Detection Ground Truth (mAP, Precision, Recall):**  
   ในเครื่องยังไม่มีชุดภาพทดสอบที่มี Label และพิกัด Bounding Box จริง จึงไม่สามารถคำนวณ mAP@0.5 ได้ จำเป็นต้องถ่ายภาพสภาพแวดล้อมห้องทดลองจริง 30–50 ภาพ พร้อมทำ Annotation พิกัดจริงเพื่อนำมาคำนวณสถิติ
2. **การสอบเทียบระยะห่างจริง (Physical Distance Calibration):**  
   ระดับระยะ "ระยะใกล้เอื้อมมือถึง", "ระยะกลางบนโต๊ะ", และ "ระยะไกลในห้อง" ถูกจำแนกตามเกณฑ์ขนาดและตำแหน่งพิกเซล (Normalized Bottom-Y และ Area Ratio) ในโค้ดเท่านั้น ยังไม่มีการวัดระยะห่างจริงเป็นหน่วยเซนติเมตรด้วยเครื่องมือวัดทางกายภาพ
3. **การประเมินความพึงพอใจจากผู้ใช้จริง (User Experience & Human Evaluation):**  
   ต้องมีการทดสอบกับกลุ่มตัวอย่างผู้ใช้จริงหรือจำลองการใช้งานจริงเพื่อเก็บคะแนน MOS (Mean Opinion Score) ด้านความชัดเจนของเสียง ความกระชับ และความปลอดภัยในการใช้งานจริง
