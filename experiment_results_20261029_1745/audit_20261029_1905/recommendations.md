## 1. การแก้ไขตัวเลขและสถิติในบทที่ 4 (Statistical Corrections)

1. **แก้ไขตัวเลขสถิติรวมของ Vision Pipeline ในตารางที่ 4.1:**
   - *ปัญหาที่พบ:* ในตารางเดิม ค่ามัธยฐาน (267.86 ms), ต่ำสุด (243.59 ms), สูงสุด (464.03 ms), และ P95 (316.35 ms) ถูกคำนวณโดยการนำค่าสถิติของแต่ละขั้นตอนย่อยมาบวกกันในแนวคอลัมน์ ซึ่งไม่ถูกต้องตามหลักสถิติ (Median of Sum ≠ Sum of Medians)
   - *ค่าที่ต้องแก้ตามข้อมูลดิบ per-iteration (N=30):*
     - **ค่าเฉลี่ย (Mean):** `275.83 ms` (ใกล้เคียงเดิม 275.84 ms)
     - **มัธยฐาน (Median):** แก้จาก `267.86 ms` เป็น **`268.97 ms`**
     - **ค่าต่ำสุด (Min):** แก้จาก `243.59 ms` เป็น **`246.40 ms`**
     - **ค่าสูงสุด (Max):** แก้จาก `464.03 ms` เป็น **`426.28 ms`**
     - **ค่า P95:** แก้จาก `316.35 ms` เป็น **`298.29 ms`**

2. **ระบุแหล่งที่มาและขนาดตัวอย่างของแถว Local LLM ในตารางที่ 4.1:**
   - *ปัญหาที่พบ:* ในตารางเดิมระบุ `N=10` มีค่ามิน-แมกซ์ 5,178.6 ถึง 11,719.2 ms แต่ในไฟล์ `latency_raw.csv` การทดสอบ LLM 10 รอบเกิด Timeout ที่ 12 วินาทีทั้งหมด โดยตัวเลข 5,178–11,719 ms ดึงมาจาก `llm_evaluation.csv` ซึ่งมีขนาดตัวอย่าง **N=7** สถานการณ์
   - *ข้อเสนอแนะ:* ให้ระบุหมายเหตุกำกับอย่างชัดเจนว่าตัวเลขสถิติเวลาของ LLM นำมาจากชุดทดสอบคุณภาพ 7 สถานการณ์ (`N=7`) ส่วนการทดสอบด้วย Prompt ขนาดยาวในชุดทดสอบ Latency เกิด Client Timeout (>12s)

3. **ชี้แจงสถานะของตัวเลข End-to-End Latency (~276 ms และ ~10.5 s) ในตารางที่ 4.2:**
   - *ปัญหาที่พบ:* ตัวเลขเวลารวมทั้งสองโหมดไม่ได้มาจากการจับเวลาด้วย Monolithic Timer ตั้งแต่เฟรมแรกจนถึงเสียงออก แต่มาจากการนำค่าเฉลี่ยของขั้นตอนย่อยมารวมกัน (Additive Synthetic Estimate)
   - *ข้อเสนอแนะ:* ให้ระบุในหัวตารางหรือเชิงอรรถว่าเป็น **“เวลาประมาณการผลรวมขั้นตอนย่อย (Additive Stage-wise Synthetic Estimate)”** เพื่อความโปร่งใสทางวิชาการ

## 2. การปรับปรุงความถูกต้องของคำศัพท์และขอบเขตการวัด (Terminology & Scope)

4. **ยกเลิกการใช้คำว่า "Zero Latency" สำหรับ Fast Path Narrative:**
   - *ปัญหาที่พบ:* รายงานเดิมใช้คำว่า Zero Latency กับการสร้างประโยคด้วย Python Rule
   - *ข้อเสนอแนะ:* เปลี่ยนเป็น **“เวลาประมวลผลระดับต่ำกว่ามิลลิวินาที (Sub-millisecond / ~0.002 ms)”** พร้อมอธิบายว่าเป็นเวลาที่วัดเฉพาะการต่อข้อความ (String Formatting) ในหน่วยความจำ

5. **ระบุขอบเขตของเวลาเสียง (Audio Latency Scope):**
   - *ปัญหาที่พบ:* เวลา gTTS (370.3 ms), Audio Cache (0.05 ms) และ Pygame (0.12 ms) อาจทำให้ผู้อ่านเข้าใจผิดว่าเป็นเวลาที่หูผู้ใช้ได้ยินเสียงจริง
   - *ข้อเสนอแนะ:* ต้องระบุชัดเจนว่าเป็น **“Software-Level Buffer Latency”** ซึ่งยังไม่รวมความล่าช้าของฮาร์ดแวร์ขยายสัญญาณเสียง (DAC / Audio Hardware Latency) หรือคลื่นเสียงเดินทางในอากาศ

6. **อธิบายสูตรคำนวณสัดส่วน RAM (27.4% vs 26.3%):**
   - *ปัญหาที่พบ:* RAM ที่ใช้ 2,056 MB เมื่อหารด้วย RAM รวม 7,819.8 MB จะได้ 26.29% แต่รายงานระบุ 27.4%
   - *ข้อเสนอแนะ:* เพิ่มคำอธิบายว่าค่า 27.4% เป็นค่าจาก `psutil.virtual_memory().percent` ซึ่งคำนวณจาก `((Total - Available) / Total) * 100` ตามมาตรฐานเคอร์เนล Linux ซึ่งรวมหน่วยความจำบัฟเฟอร์ที่ไม่สามารถคืนได้ทันที

## 3. การปรับปรุงข้อสรุปและข้อเท็จจริงในบทที่ 3 และบทที่ 5 (Methodology & Conclusions)

7. **ยืนยันสเปกฮาร์ดแวร์จริง (RAM 8 GB ไม่ใช่ 4 GB):**
   - *ปัญหาที่พบ:* ข้อเสนอโครงงานเดิมระบุ Raspberry Pi 4 RAM 4 GB แต่เครื่องทดสอบจริงเป็นรุ่น **RAM 8 GB (7.6 GiB)**
   - *ข้อเสนอแนะ:* ในบทที่ 3 ต้องระบุว่าใช้อุปกรณ์รุ่น RAM 8 GB และในบทที่ 5 ต้องระบุว่าระบบใช้ RAM จริงประมาณ 2.05 GB จึงมีความเป็นไปได้ที่จะทำงานได้บนรุ่น 4 GB แต่ยังไม่ถือว่าเป็นการพิสูจน์บนรุ่น 4 GB จนกว่าจะได้ทดสอบจริงบนบอร์ดรุ่นนั้น

8. **ระบุสถานะของสมมติฐาน Context Window Saturation:**
   - *ปัญหาที่พบ:* รายงานสรุปว่าการชนขอบเขต Context 256 โทเคนเป็นสาเหตุของความล่าช้า
   - *ข้อเสนอแนะ:* ให้ระบุว่าเป็น **“ปัจจัยร่วมที่มีหลักฐานสนับสนุนจากบันทึกระบบ (Supported Contributing Factor)”** ควบคู่ไปกับขีดจำกัดพลังการประมวลผลพื้นฐานของ CPU Cortex-A72 ซึ่งทำให้การประมวลผลโมเดลภาษา 0.5B บน CPU มีความเร็วจำกัดที่ประมาณ 7–11 tokens/sec อยู่แล้ว

9. **แยกประเภทการทดสอบคอมพิวเตอร์วิทัศน์ออกจากสภาพแวดล้อมจริง:**
   - *ปัญหาที่พบ:* การระบุว่าสี ทิศทาง และความสัมพันธ์ “ถูกต้อง 100%” อาจทำให้เข้าใจผิดว่าระบบทำงานสมบูรณ์ในทุกสภาพแสงจริง
   - *ข้อเสนอแนะ:* ต้องระบุว่าเป็นการทดสอบแบบ **“Unit Test / Controlled Logic Verification”** โดยใช้แถบสีมาตรฐานและพิกัดเรขาคณิตสังเคราะห์ ยังไม่ใช่การทดสอบความถูกต้องภายใต้แสงสะท้อนหรือการบดบังในสภาพแวดล้อมจริง

10. **เน้นย้ำข้อจำกัดด้านความปลอดภัยในการนำทาง (Safety Disclaimer):**
